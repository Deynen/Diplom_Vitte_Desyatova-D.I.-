## Краткое описание проекта
Разработана реляционная база данных для автоматизации процессов учёта заказов в интернет-магазине бытовой техники. Система заменяет ручной учёт, обеспечивая:
- Автоматическое формирование и отслеживание заказов
- Управление товарным ассортиментом и категориями
- Контроль статусов оплаты и выполнения заказов
- Генерацию отчётов и аналитику

## Цели и задачи
**Цель:** Повышение эффективности работы менеджера по продажам за счёт автоматизации учётных операций.

**Задачи:**
- Анализ предметной области интернет-магазина бытовой техники
- Проектирование нормализованной реляционной модели данных
- Реализация базы данных на MySQL с использованием хранимых процедур, функций и триггеров
- Обеспечение целостности данных и автоматизации бизнес-логики
- Создание интерфейсов для взаимодействия пользователей с системой

Customer (1) ---< (M) OrderCustomer (1) ---< (M) OrderCustomerMerchandise (M) >--- (1) Merchandise
|
(1) Category

### Описание таблиц
1. **category** - Категории товаров (посудомоечные машины, плиты и т.д.)
2. **producer** - Производители техники (BRAUN, TEFAL, SAMSUNG и др.)
3. **merchandise** - Товары с атрибутами (цена, описание, производитель, категория)
4. **customer** - Клиенты магазина (реквизиты, контакты)
5. **ordercustomer** - Заказы (дата, статус, сумма, связь с клиентом)
6. **ordercustomermerchandise** - Позиции заказа (товар, количество)

### Ключевые ограничения целостности
- Внешние ключи с каскадным удалением и обновлением
- Автоинкрементные первичные ключи
- Проверка значений через триггеры

## Функциональные возможности

### 1. Автоматический пересчёт сумм заказа
**Триггеры:**
- `OrderAfterInsert` - при добавлении позиции в заказ
- `OrderAfterUpdate` - при изменении позиции
- `OrderAfterDelete` - при удалении позиции

*Пример:* Сумма заказа автоматически пересчитывается при любом изменении состава заказа.

### 2. Хранимые процедуры
- **`InsertOrder(idcustomerIN)`** - создание нового заказа с установкой статусов по умолчанию
- **`CountMerchandise(idorderIN, OUT countorderOUT)`** - подсчёт общего количества товаров в заказе
- **`FindCustomer(fioIN, OUT result)`** - поиск покупателя по ФИО с обработкой отсутствия
- **`OrderCountStreack(dateIN, OUT result)`** - подсчёт серии выполненных заказов с использованием курсора

### 3. Пользовательские функции
- **`MaxPriceMerchandise()`** - возвращает максимальную цену товара в каталоге
- **`CountOrderClient()`** - подсчитывает выполненные и оплаченные заказы за текущий год
- **`PriceUp()`** - увеличивает цены всех товаров на 20% (демонстрация массового обновления)

### 4. Представления
- **`OrdercustomerView`** - сводная информация по заказам:
  - Дата и номер заказа
  - Данные клиента (ФИО, телефон, адрес)
  - Статусы выполнения и оплаты
  - Общее количество товаров в заказе
  - Сортировка по дате (новые сверху)

### 5. Курсор
- **В процедуре `OrderCountStreack`** - последовательная обработка записей для определения "серии успеха" (подряд выполненных заказов)
